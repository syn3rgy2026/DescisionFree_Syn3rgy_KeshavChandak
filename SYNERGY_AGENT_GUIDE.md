
# SYNERGY AGENT — Complete Project Guide
## SYN3RGY 3.0 | AI/ML Track | Team of 4

---

## What Are We Building?

A CLI-based Agentic AI system. Not a chatbot. A real execution assistant.

You type a task in the terminal. The agent thinks, plans, and actually does it.
It can browse the web, write code, create files, make PowerPoints, and more.
All reasoning happens via the InferX endpoint running Gemma 4 31B.

---

## The Big Picture — How Everything Connects

```
You type a task in the terminal
              ↓
         main.py receives it
              ↓
     core_agent.py builds the brain:
     master_prompt + memory + skills + task
              ↓
     CodeAgent (smolagents) starts thinking
     using InferX / Gemma 4 31B
              ↓
     Agent decides what action to take
              ↓
     Calls a tool from tools/ folder
     (browser, file, shell, or asks human)
              ↓
     Tool runs and returns result
              ↓
     Agent sees result and thinks again
              ↓
     Loop repeats until task is done
              ↓
     Final result printed in CLI
              ↓
     memory_manager logs the task
              ↓
     Ready for next input
```

## How Memory Works

There are 3 types of memory:

**Type 1 — Conversation memory (within one session)**
smolagents handles this automatically. You don't build anything.

**Type 2 — User memory (across sessions)**
Saved in user_memory.md on disk. Things like:
- User's name and preferences
- What projects they're working on
- What they like and dislike

**Type 3 — Task log (what was done before)**
Saved in task_log.md on disk. Every completed task is appended with a timestamp.

**The injection pattern:**
Every session start, Person 4's build_context_prompt() combines both files
into one string that Person 1 injects into the system prompt.
The agent reads this and behaves like it remembers everything.

---

## How Skills Work

Skills are markdown files that teach the agent HOW to do something well.

The skill_router reads the user's task, detects keywords, and loads the
right skill files automatically before the agent starts working.

```
Task contains "ppt" or "slides"    → load ppt_skill.md
Task contains "email" or "mail"    → load email_skill.md
Task contains "code" or "script"   → load code_skill.md
Task contains "scrape" or "web"    → load web_skill.md
Task contains "file" or "save"     → load file_skill.md
Always                             → load core_agent_skill.md
```

Without skills — agent creates output that technically works but looks bad.
With skills — agent follows real best practices and produces quality output.

---

## How Human Confirmation Works

Instead of blocking dangerous commands silently, the agent ASKS YOU first.

Before any risky action the agent calls ask_human_confirmation() which:
1. Pauses everything
2. Shows you clearly what it wants to do and why
3. Waits for you to type YES, NO, or alternative instructions
4. Agent acts based on your response

Risky actions that always need confirmation:
- Deleting any file
- Sending any email
- Submitting any form
- Running a script the agent itself wrote
- Installing any package
- Any action that cannot be undone

## main.py — What To Build

A CLI loop that never stops until user types "exit".

On startup:
- Print a welcome banner using rich Panel: "SYNERGY AGENT — SYN3RGY 3.0"
- Call memory_manager.build_context_prompt() and show a brief "I remember:" section
- Show available commands

The loop:
- Show ">>> " prompt
- Wait for user input
- If "exit" → save memory and quit cleanly
- If "memory" → print full user_memory.md contents
- If "history" → print last 5 tasks from task_log.md
- If "clear memory" → call memory_manager.clear_memory()
- If "help" → show commands again
- Anything else → call run_with_recovery(agent, task)

After every task:
- Call memory_manager.log_task(task, result, success)
- Show result using rich formatting

Use rich for all output. Use a spinner while agent is thinking.
Catch KeyboardInterrupt cleanly and print "Goodbye!"

---

## agent/core_agent.py — What To Build

Two functions:

**build_agent(task)**
1. Read agent/prompts/master_prompt.md as a string
2. Call memory_manager.build_context_prompt() — get memory as string
3. Call skill_router.get_skills_for_task(task) — get skill files as string
4. Combine all three into one system_prompt string
5. Create and return a CodeAgent from smolagents with:
   - model = OpenAIServerModel(model_id, api_base, api_key) from config
   - tools = import ALL_TOOLS from tools/__init__.py
   - system_prompt = combined prompt from step 4
   - max_steps = MAX_STEPS from config

**run_agent(task)**
1. Call build_agent(task)
2. Call agent.run(task)
3. Return the result

---

## agent/skill_router.py — What To Build

**get_skills_for_task(task)**
- Always load core_agent_skill.md
- Check task string (lowercase) for keywords:
  - "ppt", "presentation", "slides", "powerpoint" → load ppt_skill.md
  - "email", "mail", "send message" → load email_skill.md
  - "code", "script", "function", "build", "create" → load code_skill.md
  - "scrape", "website", "browse", "search", "web" → load web_skill.md
  - "file", "folder", "save", "read", "write" → load file_skill.md
- Combine all loaded skill contents into one string with separators
- Return that combined string

**load_skill(filename)**
- Read file from SKILLS_FOLDER
- Return contents as string
- If file not found: print warning and return empty string

Add a test block at bottom under if __name__ == "__main__":
- Test with 5 different sample tasks
- Print which skills were loaded for each

---

## agent/error_recovery.py — What To Build

**run_with_recovery(agent, task)**
1. Try agent.run(task) — up to 3 attempts
2. On failure:
   - Catch the exception
   - Print what went wrong in red using rich
   - Modify task to include error context:
     "Previous attempt failed with: [error]. Try different approach. Original task: [task]"
   - Wait 2 seconds
   - Show attempt number (Attempt 2/3...)
3. After 3 failures:
   - Print clear failure message
   - Ask user: "Would you like to rephrase the task? (yes/no)"
   - If yes: take new input and try again
   - If no: return failure summary gracefully

## agent/prompts/master_prompt.md — What To Write

Include:

- Keep communication concise and progress-focused

## tools/human_confirm.py — What To Build

This is the most important file you own.

**ask_human_confirmation(action, reason, risk_level)**

smolagents @tool decorator. The agent calls this before anything dangerous.

What it does:
1. Print a formatted box using rich showing:
   - Action: what the agent wants to do
   - Reason: why it wants to do it

   - Type YES to allow
   - Type NO to cancel
   - Or type alternative instructions
3. Wait for user input
4. Return user's response as a string
5. Agent reads this and acts accordingly

Tool description (very important — agent reads this to know when to use it):
"Use this before doing anything that cannot be undone. This includes:
deleting files, sending emails, submitting forms, running generated
scripts, installing packages, any irreversible action."

## tools/browser_tool.py — What To Build

Four smolagents tools:

**visit_url(url)**
Description: "Visit any URL and return the full text content of the page."
Implementation: requests + BeautifulSoup
- Fetch the page
- Extract all text content cleanly
- Return as string
- Handle connection errors gracefully

**search_web(query)**
Description: "Search the web for any query and return top results with titles and URLs."
Implementation: DuckDuckGo search via requests
- Return formatted list of results with title and URL
- Handle no results case

**get_page_links(url)**
Description: "Get all links found on a webpage. Returns list of URLs."
Implementation: requests + BeautifulSoup find all href
- Return clean list of links
- Filter out empty and javascript: links

**fill_and_submit_form(url, form_data)**
Description: "Fill and submit a form. form_data is JSON string of field names and values.
ALWAYS calls ask_human_confirmation before submitting."
Implementation: Playwright
- ALWAYS call ask_human_confirmation first with risk_level HIGH
- Fill form fields
- Submit only if human confirms
- Return success or failure message

Test block at bottom:
- Test visit_url with "https://example.com"
- Test search_web with "smolagents python framework"
- Print results to verify

## tools/shell_tool.py — What To Build

Two smolagents tools:

**run_command(command)**
Description: "Run a shell command and return output. Asks human confirmation before risky commands."

Risky command detection — check if command contains any of:
- rm
- sudo
- pip install
- /etc/
- /sys/
- /usr/
- format
- shutdown

If risky: call ask_human_confirmation with risk_level HIGH before running
If confirmed or safe: run with subprocess
- Capture both stdout and stderr
- Apply SHELL_TIMEOUT from config
- If timeout: return "Command timed out after X seconds"
- Return stdout + stderr combined

**run_safe_command(command)**
Description: "Run pre-approved safe commands without confirmation.
Safe list: ls, pwd, python --version, pip list, cat, echo, mkdir, cd, which, whoami, git status"

- Check command starts with something from the safe list
- If not in safe list: call run_command instead (which handles confirmation)
- Run and return output

## How To Write Good Skill Files

Think of each file as briefing notes for a new employee before they start a task.
Tell them exactly what good output looks like. Be specific. Use examples.
If a rule is vague the agent will interpret it loosely. Be precise.

Read each file out loud after writing. If it sounds clear to you, it will work.

## skills/core_agent_skill.md — What To Write

This file gets loaded for EVERY task always.

Include:
- How to plan tasks: list all steps before starting, number them
- Progress format: always use [Step X/Y] Doing something...
- How to handle failures: try different approach, don't give up
- How to verify output: check file exists, check it has content
- When task is done: say "Done." then list what was created
- Never stop halfway through a task
- If blocked 3 times: explain clearly what failed and ask user

---

## skills/ppt_skill.md — What To Write

Slide structure rules:
- Slide 1: Title only + one line subtitle
- Slide 2: Agenda or overview of what will be covered
- Middle slides: one topic per slide, no more
- Last slide: Summary + next steps or thank you

Content rules:
- Maximum 5 bullet points per slide
- Maximum 10 words per bullet point
- Every slide must have a header
- Use numbers and data wherever possible
- Never paste full paragraphs onto slides

Design rules:
- Use base_template.pptx if it exists in skills/ folder
- Dark blue for all headers
- White or very light background
- Suggest where images or diagrams should go even if you cannot add them

Technical:
- Use python-pptx library
- Always save as .pptx not .ppt
- Save to OUTPUT_FOLDER from config
- Name file clearly: topic_YYYY-MM-DD.pptx

---

## skills/email_skill.md — What To Write

Subject line:
- Under 8 words
- Be specific not vague
- Bad: "Following up" — Good: "Proposal for AI project partnership"

Opening line:
- Get to the point immediately in the very first sentence
- Never write "I hope this email finds you well"
- Never write "I am writing to you regarding"

Body:
- Under 150 words for normal emails
- Short paragraphs, 2-3 sentences maximum per paragraph
- One idea per paragraph only

Closing:
- End with exactly ONE clear action the reader should take
- "Please reply by Friday with your availability"
- Never end without telling them what to do next

Tone:
- Professional but human, not robotic
- Confident but not aggressive
- If asking for something: briefly explain why in one sentence

---

## skills/code_skill.md — What To Write

Before writing code:
- Understand the full requirement before touching the keyboard
- Check if a library already exists that does this
- Plan the structure: what functions are needed, what inputs and outputs

While writing:
- Add a comment explaining WHY not just what
- Handle every possible error explicitly
- Never use bare except without specifying the exception type
- Use meaningful variable names, never single letters except in loops

After writing:
- Actually run the code and verify it works
- Check what happens with edge cases
- If it fails: read the full error message before making changes

Structure rules:
- Each function should do exactly one thing
- Keep functions under 20 lines if possible
- Put main logic under if __name__ == "__main__"

---

## skills/web_skill.md — What To Write

Before scraping:
- Check if the site has an official API first
- If an API exists: use it, do not scrape
- Only scrape when no API is available

While scraping:
- Add 1-2 second delay between requests, never hammer a server
- Always check if an element exists before accessing it
- Save raw HTML to a file first before processing
- Verify the data looks correct before saving final output

If blocked:
- Try changing the user agent string
- Try adding longer delays between requests
- Try a slightly different URL structure
- If still blocked: tell user this site cannot be accessed and why

Data quality:
- Remove completely empty rows before saving
- Strip whitespace from all text fields
- Verify row count makes sense before declaring done

---

## skills/file_skill.md — What To Write

Naming rules:
- Use lowercase with underscores, no spaces
- Be specific: report_ai_frameworks_2025.csv not results.csv
- Include date if file will be updated over time

Organization:
- Always save final outputs to OUTPUT_FOLDER from config
- Never save to the root project folder
- Create subfolders for different task types if there are many files

Before saving:
- Check if file already exists
- If it does: call ask_human_confirmation before overwriting

After saving:
- Confirm the file actually exists
- Check it has content and is not empty
- Tell user the exact full path where it was saved
- Tell user the file size

## memory/memory_manager.py — What To Build

Build a MemoryManager class with these methods:

---

**load_user_memory() → str**
- Read user_memory.md from MEMORY_FOLDER
- Return contents as string
- Return empty string if file does not exist yet

---

**save_user_memory(new_info: str)**
- Open user_memory.md in append mode
- Write a timestamp header then the new info
- Format:
```
[2026-04-18 14:32]
- User's name is Raj
- User is building a hackathon project
- User prefers Python over JavaScript
```

---

**extract_user_info(conversation: str) → str**
- Takes the full conversation text from a session
- Calls InferX via openai library with this prompt:
  "From this conversation, extract only new facts learned
   about the user. Return as bullet points starting with -.
   Only include concrete facts. If nothing new, return NOTHING."
- Returns the extracted facts string
- This gets called at end of session and passed to save_user_memory

---

**log_task(task: str, result: str, success: bool)**
- Open task_log.md in append mode
- Write entry in this format:
```
[2026-04-18 14:35]
TASK: Create a PPT about AI frameworks
RESULT: Created file at output/ai_frameworks_2026-04-18.pptx
SUCCESS: Yes
---
```

---

**load_recent_tasks(n: int = 5) → str**
- Read task_log.md
- Parse the entries (split by "---")
- Return the last n entries as a formatted string
- Return empty string if file does not exist

---

**build_context_prompt() → str**
- Call load_user_memory()
- Call load_recent_tasks(5)
- Combine into this exact format and return:

```
=== WHAT YOU KNOW ABOUT THE USER ===
[user memory contents here]

=== RECENT TASKS COMPLETED ===
[recent tasks contents here]
```

This is what Person 1 injects into the system prompt at the start of every session.

---

**clear_memory(confirm: bool = False)**
- If confirm is False: ask user to type "yes" to confirm
- If confirmed: delete user_memory.md and task_log.md
- Print "Memory cleared successfully"

---

At the bottom of the file create a module-level instance:
```python
memory_manager = MemoryManager()
```

So Person 1 can import and use it like:
```python
from memory.memory_manager import memory_manager
context = memory_manager.build_context_prompt()
```
